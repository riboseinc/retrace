# 05 — Public library API

**Status**: [~] in progress (scaffold written, see `include/retrace/retrace.h`)
**Layer**: 5 (public surface)
**Depends on**: 02, 03, 04
**Blocks**: 06, 07

## Goal

Define the public C API that downstream consumers link against. The library
must be embeddable (a test framework injects malloc failures), scriptable
(build a script in C without parsing), and hermetic (deterministic given
script + target).

The header scaffold is committed at `include/retrace/retrace.h` with target
types and function signatures. Implementation lands incrementally as
TODOs 02-04 land.

## Why

Without a public API:
- Every consumer must shell out to the `retrace` CLI.
- Test frameworks (cmocka, libcheck, Google Test) can't integrate retrace.
- Security tools (fuzzers, SAST) can't drive retrace programmatically.
- FFI bindings (Ruby, Python, Go) have nothing stable to bind to.

## API surface

All types are opaque handles — callers never see struct definitions. ABI
stability is achieved via opaque pointers + versioned symbols visibility.

## ABI stability

- All public types are forward-declared opaque structs in the public header.
  Struct definitions live in `src/core/internal/*.h` and are never installed.
- Public functions are tagged `__attribute__((visibility("default")))` on ELF
  and `__attribute__((visibility("default")))` on Mach-O; everything else is
  `__attribute__((visibility("hidden")))`.
- Symbol versioning via `.symver` on ELF: `retrace_engine_create@RETRACE_2.0`.
- Header versioning: `RETRACE_VERSION_MAJOR` changes only on ABI break.

### [P0] Visibility annotations
- [ ] Add `RETRACE_API` macro (`__attribute__((visibility("default")))`) to every public function
- [ ] Add `RETRACE_INTERNAL` macro (`__attribute__((visibility("hidden")))`) as default
- [ ] CMake: `set(CMAKE_C_VISIBILITY_PRESET hidden)` + `set(CMAKE_VISIBILITY_INLINES_HIDDEN ON)`
- [ ] ELF `.symver` script in `cmake/retrace.exports.map`

### [P0] Error handling
- [ ] Replace ad-hoc `log_err(...)` calls in public-API code paths with thread-local error stack
- [ ] Every public function returns `int` (0 on success, negative on error)
- [ ] `retrace_last_error(eng)` returns the most recent error message
- [ ] Ctor/dtor pair for thread-local error buffer

### [P1] Custom actions from outside the library
- [ ] `retrace_engine_register_action(eng, name, fn, schema)` lets users add actions without rebuilding
- [ ] Action schema (parameter types) is declared so the script validator can check

### [P1] FFI-friendly design
- [ ] All opaque handles are pointers (not values) — easy to box in Ruby/Python
- [ ] All string returns are `const char *` owned by the engine until next call
- [ ] All output buffers are caller-allocated with size parameter

### [P2] Stable serialization
- [ ] `retrace_script_serialize(script, char **out)` produces canonical JSON
- [ ] Round-trip stable: `parse(serialize(s)) == s`

## Acceptance criteria

- `nm -D libretrace.so | grep ' T '` shows only functions tagged `RETRACE_API`.
  All other symbols are hidden.
- An external project can `find_package(retrace CONFIG REQUIRED)`,
  `target_link_libraries(app PRIVATE retrace::core)`, and call
  `retrace_engine_create()` without including any internal header.
- Ruby FFI / Python ctypes binding is achievable with no struct layout
  knowledge (only opaque pointer manipulation).

## Open questions

- Should we ship a separate `libretrace-cxx` C++ wrapper with RAII? Lean
  toward no for v2.0 — keep the API surface small. A separate wrapper can be
  added later.
- Do we promise strict ABI stability from 2.0.0, or "best effort" until 2.1?
  Lean toward strict from 2.0.0 — once published, breaking ABI is painful.
